# LangGraph 文档翻译

> 通用机翻能把 LangGraph 文档翻出个大概，但真正的差距在**术语一致、代码不碰、指代清晰、语气对路**这四件事上。本技能给的是判定标准与检查清单：什么该直译、什么必须保留原文、代码怎么处理、翻完怎么自查、什么情况不能交。

## 一、这个技能解决什么（定位 + 人群）

- **谁用**：翻译 LangGraph 官方文档（概念指南、教程、How-to 指南、API 参考、版本发布说明）的译者，以及需要审校机翻结果的译者。
- **典型场景**：一个概念在全文出现多种叫法（graph / 图 / 图表 / 计算图）；代码块被机器改坏；API 名、参数名、类名被翻译成中文；长定语从句直译后逻辑颠倒；`you` / `we` 的人称处理前后不一致；不确定内联代码里的英文要不要翻。
- **本技能不做什么**：不负责源码本身；不保证与某一具体版本的行为完全一致（版本相关描述以官方文档对应版本为准）；只给方法论、判定标准和检查清单。

## 二、LangGraph 文档的特殊性（为什么不能套通用翻译）

LangGraph 是构建有状态、multi-agent 应用（stateful, multi-agent applications）的框架，其文档与普通技术文档有四处关键差异：

1. **代码密度高**：几乎每个概念都带代码示例，代码块是"不可翻译区"。
2. **术语强绑定 API**：`node`、`edge`、`state`、`checkpoint` 等既是自然语言又是 API 概念，翻错一处会连锁误导。
3. **新旧概念混杂**：`StateGraph`、`send`、`Command`、`Pregel` 等概念有明确的指代对象，不能望文生义。
4. **阅读路径是文档 ↔ 源码**：读者会拿着译文去对照源码，译文中的命名必须能一对一映射回源码标识符。

## 三、文本类型分层：先定类型，再定自由度

| 文本类型 | 首要目标 | 可改写程度 | 硬约束 |
|---|---|---|---|
| API 参考 | 精确、可对照源码 | 极低，逐句对应 | 类名/函数名/参数名/类型注解不改；签名与默认值零偏差 |
| 概念指南 | 准确、概念清晰 | 低，句式可调整 | 术语与指代对象一致；不得引入原文没有的概念 |
| 教程 / 快速入门 | 可操作、能跑通 | 中，步骤可重组表达 | 步骤顺序、代码、命令不得变；输入输出不得改写 |
| How-to 指南 | 达成目标 | 中 | 目标与前置条件不得遗漏 |
| 版本发布说明 | 如实传达变更 | 低 | 版本号、日期、破坏性变更不得增删 |

判定规则：**先看"出错代价"与"是否可对照源码"**。API 参考与概念指南出错代价最高、且会被拿去对照源码，自由度最低。

## 四、术语治理（最容易被跳过，也最容易翻车）

### 术语表字段

| 字段 | 要求 | 说明 |
|---|---|---|
| 源词 | 原文形式 | 含大小写、单复数、连字符（如 `checkpointer` / `Checkpoint`） |
| 译词 | 唯一确定 | 一个源词只对应一个译词；"不翻译"表示保留英文 |
| 禁用译法 | 列出常见错译 | 防"同词多译" |
| 说明 | 为什么这么译 / 指向哪个对象 | 解决一词多义与指代 |

### 术语表（见 [references/terminology.md](references/terminology.md)）

完整术语表与一致性约定独立维护在 [references/terminology.md](references/terminology.md)，翻译时以此为唯一依据，不在正文内重复。

### 使用规则

- `graph` / `node` / `edge` / `state` 等强绑定 API 的核心概念一律保留英文。
- 术语表里没有的词：先判断是否属于"类名 / API / 参数名 / 产品名"——是则保留英文；否则登记待定，不现场拍板。
- 标点、混排空格、人称、产品名等一致性约定见 [references/terminology.md](references/terminology.md) 末尾「一致性约定」。

### 一致性检查（交付前必跑）

1. 提取全文高频名词与专有名词（出现 ≥ 3 次）。
2. 逐一核对：同一源词是否只用一个译词。
3. 检查代词与指代：英文 `it / they / this` 回到中文后指代是否明确，尤其指代的是 `node` / `state` / `graph` 中的哪一个。
4. 检查中英混排：英文与中文之间是否留半角空格；标点是否全用半角。

阈值：**同一术语在全文出现 3 次以上却有 2 种以上译法，即为不合格**，必须回头统一。这是审校时最常见的一票否决项。

## 五、代码与格式保持规则（LangGraph 文档的核心）

### 代码块：不翻译

- **多行代码块（``` 包裹）整体保留原样**，不改缩进、不改引号、不改换行。
- 代码块内的**注释与字符串默认保留原文**；如需翻译，只在注释与字符串内翻译，且**绝不能改动任何可执行代码**。
- 命令示例（`pip install`、`npm run` 等）原样保留。

### 内联代码：保留英文

- 内联代码（反引号包裹的 `StateGraph`、`add_node`、`MessagesState` 等）一律保留英文，不翻译、不加引号。
- 内联代码是"指向源码的锚点"，翻译即断链。

### 命名规范：专有名词保留英文

| 类型 | 处理 | 示例 |
|---|---|---|
| 类名 / 函数名 / 方法名 | 保留原文 | `StateGraph`、`add_node`、`invoke` |
| 参数名 / 属性名 | 保留原文 | `state_schema`、`recursion_limit` |
| 框架 / 库 / 产品名 | 保留原文 | `LangGraph`、`LangChain`、`LangSmith` |
| 可译概念 | 按术语表翻译 | `orchestration` → 编排、`checkpointer` → 检查点保存器 |
| 强绑 API 概念 | 保留英文 | `graph`、`node`、`edge`、`state` |
| 首次出现的概念 | 可"译词（原文）"并注 | 检查点保存器（Checkpointer） |

### 文档格式：保持原样

翻译时**只翻译文字内容，不改动任何 markdown 结构**。以下格式一律原样保留：

| 格式元素 | 处理 |
|---|---|
| 标题层级（`#` / `##` / `###`） | 保留层级与数量，只译标题文字 |
| 列表与表格 | 结构、列数、行数不变，只译条目/单元格文字 |
| 代码块与语言标签 | 整体保留，语言标签（python / python-no-test 等）不改 |
| 链接与锚点 | URL、相对路径、锚点 deep link 不改；链接文字可译 |
| 图片 | 路径不改，alt 默认不改 |
| Admonition 提示块 | `!!! note` / `!!! tip` / `!!! warning` 语法保留，只译标题与正文 |
| 强调与行内格式 | 加粗、斜体、行内代码的对应关系保持一致 |

机翻最容易破坏的是 admonition（`!!!` 语法）与代码块语言标签，交付前重点回验这两类。

### 概念与代码同词时的判定

`graph`、`state`、`node` 等既是自然语言又是 API 概念，本技能统一**保留英文不译**（见 [references/terminology.md](references/terminology.md)）；其余能译成自然中文的按术语表译词执行。凡是能对照到源码标识符的，一律保留英文。

## 六、质量三维评分卡

| 维度 | 判什么 | 0–4 分标准 | 达标线 |
|---|---|---|---|
| 忠实度 | 有没有漏译、错译、加戏 | 0=有事实/代码错误；2=个别漏译；4=完全对应 | ≥ 3.5 |
| 通顺度 | 目标语言是否自然 | 0=机翻腔明显；2=能懂但别扭；4=母语感 | ≥ 3 |
| 术语一致性 | 术语、命名、指代是否统一 | 0=前后矛盾；2=偶有跳脱；4=全文统一 | ≥ 3 |

用法：三段式打分后取最低分作为该译文的等级。**任一维低于达标线即需返工**，不看平均分——平均分会掩盖致命错误。

## 七、LangGraph 文档高频陷阱对照表

| 陷阱 | 表现 | 改法 |
|---|---|---|
| 定语堆叠 | 英文长定语从句直译为中文"……的……的……" | 拆成短句或改述为"……，其……" |
| 术语漂移 | `graph` 一会译"图"一会译"图表"，`state` 一会保留一会译成"状态" | 对照术语表统一，全文只用一个译词（或统一保留英文） |
| 代码被改 | 机翻把代码块里的标识符/参数动了 | 逐块 diff，代码块与源码对齐 |
| 指代不清 | `it / this` 翻成"它/这"，不知指 `node` / `state` / `graph` 哪一个 | 补出真实指代对象，还原具体名词 |
| 概念望文生义 | 把 `Command` 直译成"命令"、把 `send` 当"发送" | 查术语表与官方文档定义，不凭直觉 |
| `you / we` 人称 | "you"翻成"您/你"前后不一致 | 全文统一用"你"，不混用"您" |
| 被动语态 | 英文被动直译成生硬中文 | 改主动或补主语（"系统会…""框架将…"） |
| 版本号与数字 | 版本号、参数默认值被改 | 逐项回验，数字与源码一致 |
| 中英混排空格 | 中文与英文之间不留空格 | 中英文之间、中英文与数字之间留半角空格 |
| 标点 | 中文全角与英文半角混用 | 全用半角；代码与英文名保持半角 |

## 八、译后编辑（MTPE）：判定机翻能不能用

| 判定项 | 轻度编辑（可快速交付） | 重度编辑（需重写） |
|---|---|---|
| 术语 | 一致，或少量统一即可 | 全文术语混乱 |
| 代码 | 代码块未动，内联代码保留 | 代码块被改动 / 标识符被翻译 |
| 句法 | 个别长句需拆 | 逻辑顺序错乱 |
| 指代 | 基本清晰 | `it/this` 大面积指代不明 |
| 漏译 | 无 | 有整句 / 整段缺失 |

编辑顺序（固定，不要跳步）：
1. **先对代码**：代码块、内联代码、命令与源码逐一对齐，改坏一处全废。
2. **再对格式**：标题层级、列表/表格结构、链接锚点、admonition、语言标签逐项回验。
3. **再统术语**：全文搜索替换，统一到术语表。
4. **再顺句子**：拆长句、修指代、补主语。
5. **最后调语气**：人称、敬语、风格统一。

## 九、标准工作流（5 步）

1. **定类型与自由度**：API 参考 / 概念指南走低自由度，教程 / How-to 走中自由度。
2. **对术语表**：先查 [references/terminology.md](references/terminology.md)；表里没有的词先登记待定，不现场拍板。
3. **译**：按类型套译法；代码块原样保留；长句先断句再组句。
4. **自查**：跑一致性检查 + 代码/格式对齐 + 陷阱表 + 三维评分。
5. **回验**：脱离原文只读译文一遍——读不顺的地方，八成有错；再拿译文对照源码点一遍关键标识符。

## 十、红线与边界

1. 代码块与内联代码中的标识符、参数、默认值一律不得改动；只可在注释与字符串内做翻译。
2. 不得增删改原文的事实、版本号、数字、条件与行为描述。发现原文自相矛盾或与源码不符，应提出疑问而非自行修正。
3. 未出现在术语表中的专有名词，先登记待定，不得凭直觉翻译。
4. 涉及未公开的内部代码、密钥、环境变量，不得提交至任何外部翻译服务。
5. 译文交付时须标注源文档版本与翻译日期，便于后续版本对齐。

## 十一、模板清单

1. **术语表模板**：源词 / 译词 / 禁用译法 / 说明
2. **待定词清单**：源词 / 出现位置 / 为什么待定 / 决定后的译词
3. **一致性检查单**：高频名词清单 / 译法是否唯一 / 指代是否清晰 / 混排空格
4. **代码对齐清单**：代码块 diff / 内联代码保留 / 命令原样
5. **三维评分卡**：忠实度 / 通顺度 / 术语一致性，各 0–4 分 + 主要问题
6. **交付说明**：源文档版本 / 翻译日期 / 待确认项 / 审校状态

## 十二、FAQ

**Q：机翻结果看着挺顺，能直接交吗？**
A：先跑第五节"代码与命名处理"的对齐和第四节的一致性检查。LangGraph 文档看着顺不等于没错——最致命的是代码被改和术语漂移。

**Q：概念指南里一个概念反复出现，要不要每次都用同一个译词？**
A：要。全文只用一个译词；首次出现可加"译词（原文）"标注，之后保持一致。这是术语治理的核心。

**Q：代码块里的英文注释要不要翻译？**
A：默认保留原文，避免二次改动引入错误。若确需翻译，只翻译注释与字符串，绝不能碰可执行代码。

**Q：`StateGraph` 这种词要不要翻译？**
A：一律保留原文。类名 / API 标识符不译；`StateGraph` 这类强绑 API 的概念也保留英文（见 [references/terminology.md](references/terminology.md)），不要译成"状态图"。

**Q：同一份文档多人合译，怎么保证一致？**
A：先出术语表和风格约定（人称、代码处理、标点），再分工；合稿后统一跑一致性检查与代码对齐。顺序反了必然返工。

**Q：术语表里没有的词，遇到拿不准怎么办？**
A：先判断是否属于"类名 / API / 参数名 / 产品名"——是则保留英文；否则登记到待定词清单，等术语表更新后统一回填，不要现场拍板、更不要留下三种叫法。

## 十三、60 秒 quick start

1. 定类型：API 参考 / 概念指南低自由度，教程 / How-to 中自由度。
2. 代码块原样保留，内联代码与标识符不翻译。
3. 查 [references/terminology.md](references/terminology.md)；没有的词登记待定，不现场拍板。
4. 交付前四查：代码对齐、术语一致、指代清晰、三维评分。
5. 脱离原文通读一遍译文，再对照源码点一遍关键标识符。
